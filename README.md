# 开单分析 · crypto-entry-advisor

给一个币，把行情切段读成文字，交给大模型**预测接下来最大概率会走成什么样**，
顺带给每个形状标签一个概率。

> 不是投资建议，只做纪律辅助。

---

## 一分钟看懂它在干什么

```
拉 K 线  →  切成小段读成文字  →  拼上下文  →  调模型  →  结论 + 标签概率  →  存档
```

**核心原则：不给 AI 算口径、不给 AI 判档。**

- 以前是「代码算好趋势 / 摆动点 / 量比，AI 按 A/B/C 档填表」。
  现在代码只负责**取数**和**把 K 线读成文字**，怎么读、怎么判断全交给 AI。
- AI 输出**只有 6 个字段**：标签（带概率）、理由、走势、走势概率、结论、推荐。
- 没有止损止盈、没有仓位、没有 checklist、没有护栏校验 —— 那些都删了。
- **提示词写在代码里**（`backend/src/llm/prompts.ts`），改完要**重新部署**。
- 知识库**不注入** prompt，只借它一份**标签池**。

## 跑起来

```bash
npm install
npm run db:up          # 起 PostgreSQL（Docker）
npm run web            # 开发模式：后端 + Vite HMR，浏览器开 http://localhost:8787
```

⚠️ **同一时间只允许一个后端在跑**（2026-10-16 加的单实例锁，
见 [single-instance.ts](./backend/src/util/single-instance.ts)）：交易所的权重预算是
**按出口 IP** 算的、全站共用一条，两个实例 = 两套 WS + 两套补历史挤同一条，
报出来是「取数失败：交易所请求太频繁」，而且两个实例互相甩锅、很难查。
再起一个会被拦下并告诉你现成的那个是谁：

```bash
npm run web            # 第二个 → ✋ 已经有一个后端在跑了（pid 16483 · 端口 8787）
kill -INT <pid>        # 要重启：SIGINT 立刻退（SIGTERM 会等整分钟收盘）
ALLOW_MULTI_SERVER=1 npm run web   # 确实要两个一起跑（不推荐）
```

前端也**不用单独起**：`npm run web` 里就挂着 Vite（同一个进程、同一个端口），
所以「一个后端」= 一个前后端。多起几个前端只有 `ui:dev` 那一种情况，不影响后端。

命令行直接分析一个币：

```bash
npm run dev -- BTC/USDT                 # 默认 1h 周期、看最近 3 天（CLI 才有天数参数）
npm run dev -- BTC/USDT -t 4h -d 30     # 换周期 / 换天数
```

### 本地免登录（2026-10-15）

本地开发不想每次输密码 + 动态口令，就在起后端时带上 `DEV_AUTO_LOGIN`：

```bash
DEV_AUTO_LOGIN=1 npm run web          # 1 = admin；也可以写用户名
```

前端（**只在 vite 开发模式**）发现本地没有 token 时会自己去 `GET /api/auth/dev-login` 换一条，
拿到的是一条**正常的会话 token**（落 `sessions` 表、同样 30 天、「登录设备」里能看到也能踢）。

两道闸，缺一不可，所以线上**不成立**：

1. `NODE_ENV !== 'production'` —— 线上容器是 `production`（`docker-compose.prod.yml` / `Dockerfile`），
   命中这条直接 404；
2. 显式设了 `DEV_AUTO_LOGIN` —— 不设就永远走不到（默认关）。

⚠️ 开到它就等于「本地不用登录了」：想测登录 / 登出流程记得**别带这个变量**起后端。
⚠️ 顺带一个坑：token 存在 `localStorage`，而 `localStorage` **按 origin（含端口）隔离** ——
本地换端口（8787 ↔ 8789 ↔ 8790）就会各登各的，看着像「每次都要登录」。本地固定一个端口最省事。

环境变量放 `.env`（只剩交易所 / 数据库 / 汇率这些；`EXCHANGE` / `MARKET_TYPE` / `API_BASE` 可选）。
**大模型配置（Key / 模型 / 接口地址 / 思考力度）不放 `.env`** —— 按用户存在数据库里，
在网页「我的 → 个人信息 → 模型配置」里填；管理员能在「我的 → 管理」看每个人的配置。
网页右上角切换模型现在写的是**你自己的**配置，重启也保留；旁边那个「余额 ¥x.xx」
是模型账户还剩多少钱（`GET /api/account` → DeepSeek `/user/balance`，后端带 60 秒缓存，
**点一下才是真刷新**）。

## 线上部署

**已上线：<https://bitcoooin.cn>** —— AWS Lightsail（东京）+ Docker Compose + Caddy 自动 HTTPS。

完整步骤与运维看 [`docs/DEPLOY.md`](./docs/DEPLOY.md)，日常就一件事：

```bash
npm run release            # = bash scripts/release.sh：提交检查 → 类型检查 → 打包 → 上传 → 远端部署 → 验收
npm run release:dry        # 只看打包结果和要执行的命令，不碰服务器
```

> `package.json` 里给 `scripts/` 下那三个壳脚本各配了别名：`release` / `release:dry` /
> `deploy`（在服务器上跑）/ `apk`（打安卓包）。直接 `bash scripts/release.sh` 也一样。

它内部用 tar + scp 搬运（不要用 rsync：macOS 自带的是 openrsync，和服务器 rsync 3.x
不保证兼容），并自动排除 `.env` / `android` / `*.apk`，清掉服务器上的旧文件后再解包
—— 细节看 `docs/DEPLOY.md`。

两个最容易忘的：**Lightsail 防火墙要放行 80 / 443**；
**打包必须 `--exclude='.env'`**（服务器那份里有随机化过的 `PGPASSWORD`，被覆盖就连不上库）。

生产与开发的差别只有一个：`NODE_ENV=production` 时后端**跳过 Vite**、直接托管
`frontend/dist`，所以线上不需要 `vite` / `tsx`（镜像多阶段构建，只带生产依赖）。

### `/` 上怎么取数

- **主周期 = 图上那个周期**（5分 / 15分 / 1时 / 4时 / 日线）—— 页面上切周期，AI 看的就是它
  （不切的话两边会不一致）。
- 主周期看的就是**图上那一段**：`CHART_BARS`（`frontend/src/analyze.ts`，基准 200 根），
  实际根数**跟屏幕宽度走**（`KlineChart.vue`），换出来的天数发给后端。
  页面上**不给用户填天数**。
- 其余周期**跟着主周期走**，取多少天由 `config/calibers.yaml` 决定：

  ```yaml
  取数:
    其余周期:
      5m: {15m: 2, 1h: 10, 4h: 20, 1d: 30}
      1h: {15m: 2, 4h: 30, 1d: 60}
      15m: {1h: 10, 4h: 20, 1d: 30}
      4h: {1d: 60}
      1d: {}
    最少根数: 30
    最多根数: 1500
  ```

  ⚠️ **每一行都要写全**：漏了哪一行，那个主周期就**一个其它周期都不带**
  （5m 一开始就是漏的 → AI 只看得到最近 1 天的 5 分钟 K 线，看不到大周期方向）。
  改完即时生效，不用重启。

### 测试模式（宽屏切「测试」那格 tab；手机点 K 线头上、配置左边那颗测试图标）

回到过去某一刻看「当时」。用**结束线**指定那一刻，**不用划范围**：

- 进测试模式：宽屏点左边那格 tab，手机点 K 线头上那颗**测试图标**（在「配置」左边）——
  点完就等着你点线；**再点一下那颗图标就退出**（图上的线跟着收掉，
  但**记住**你选过的那一刻，再进来还在）
- 在 K 线上**点一根**，线就落在那根的收盘上；**已经放好的线可以直接拖**（左右拉，
  面板上的「判断时点」会跟着跳）
- **手机**：点完线自动跳到「预测结果」那一格（那儿有结束线和结论）；
  想换一根点面板里的「**重选**」——它会把你送回 K 线那格并进入选线；
  「**清掉**」= 连测试模式一起退出（手机上那颗图标在 K 线格，看不到时这是唯一的退路）
- AI 只看到**这一根收盘为止**的 K 线，之后的一根都不给
- 取数永远是「以这一刻为终点往前推 N 根」，所以**只需要一个时刻** ——
  划一段会让人误以为 AI 只看那一段（其实只有结束那一刻参与取数）
- **图本身不截断**：结束线纯粹是个输入，后面的行情照画（否则会像「后面没行情了」）
- 那一刻之后的行为，可以拿来对照 AI 当时说的走势对不对
- 资金费率 / 持仓量 / 多空比拿不到（那些接口只返回「现在」），留空
- **不存档**，不混进预测历史（页面顶上就一条「测试模式 · 判断时点 …」提醒）

⚠️ 手机上「测试」**不是一格 tab**：tab 行放不下第 5 格（4 格 + 模型余额刚好铺满），
所以走那颗图标。手机那格的图只在自己那格（「K 线」），所以「选线 → 预测结果」是一进一出。

（「添加案例」那个 tab 才是真的**拖一段**：画哪一段就提炼哪一段，那是另一套。）

- 「各周期行情」那块显示的就是**真正发给 AI 的原文** —— 每一段都标了天数、根数、起止时间。
  看着不对劲，就是这里不对劲。

## 结论长什么样

```json
{
  "tags": [
    {"name": "放量突破", "probability": 62},
    {"name": "上沿受阻", "probability": 40}
  ],
  "reason": "15m 第 5 段从 84,045 拉到 86,622，均量 1,833……",
  "outlook": "先小幅回踩 15m 第 5 段冲高后的密集区不破，再往上试 86,888 那道被反复顶到的上沿",
  "probability": 58,
  "verdict": "wait",
  "recommendation": "现在不追。等 15m 回踩到 84,900-85,300 一带、缩量且不破 84,582 再考虑……"
}
```

- `tags` 是**形状**标签 + 概率（最多 2 个，按概率高低排），不是档位。
- `outlook` 是**预测**，要写**具体价位**：先说看哪个价位、守住还是破了、然后看哪个价位。
  点位必须**带来源**（第几段的高/低点、哪道被反复碰的压力/支撑）——
  允许写点位，但不许凭空抬一个目标价、也不许说成「一定到得了」。
- `probability` 是 `outlook` 那个走法的概率。概率要有依据：
  结构越干净给得越高，两边都说得通给得越低。
- `verdict`：`go` / `wait` / `no_go` —— 现在这个价能不能进。
  **三档怎么判写在提示词里**（「结论三档」那一节）：
  `go` = 现在就能进（最可能那条路占优 + 止损找得到位置）；
  `wait` = 方向清楚但现价离进场位还有一段（提示词里会写明在等什么）；
  `no_go` = 哪个方向都不碰。拿不准 `go` 还是 `wait` 的时候偏 `go`。
  界面上显示为 **可做 / 观望 / 不可做**。

**这份骨架写死在代码里**（`backend/src/llm/prompt.ts` 的 `OUTPUT_CONTRACT`），
但**它只管格式**：字段名、类型、取值范围、必须输出 JSON。
**判定标准一条都不在里面**（怎么读行情、怎么预测、`verdict` 三档怎么分、点位怎么写）
—— 那些全在 `PREDICT_PROMPT` 里。它是程序接口，**不在网页上编辑**。
`npm run selftest` 会断言骨架里的字段名和 `zod` schema 对得上。

## 数据问答

用自然语言问**自己库里的数据**（不是行情预测）：入口在「我的 → 数据问答」（`/me?p=ask`），
接口是 `POST /api/ask`，网页走的是流式那条 `GET /api/ask/stream`。

界面照主流聊天应用那套：**左侧会话历史 + 右侧对话**（2026-10-16 用户：「界面要和现有市场上的
类似，左侧聊天历史，可折叠」）。

- **会话**（`AskThread`）存在浏览器 localStorage（`ca_ask_threads`）：第一句问题当标题，
  左侧按 **今天 / 昨天 / 7 天内 / 更早** 分组，组内按最近更新倒序；可新建、切换、删除。
- **折叠**：宽屏侧栏是并排一列；窄屏侧栏是**模态抽屉** ——
  抽屉 `z-index: 7` > 遮罩 `6` > 输入框 `5`，所以**抽屉打开时盖住输入框**（模态层该有的
  样子），收起时输入框就是最底下那个。遮罩只盖「消息 + 输入框」那一层，点它收起。
  折叠状态记在 `ca_ask_side_v2`，切页面回来还是上次那样（**默认展开**）。
- ⚠️ 窄屏的输入框用 **`position: fixed` 钉在底栏正上方**（跟底栏同一个定位基准：
  `bottom: --tabbar-h + 安全区`），不是靠 flex 撑到底再 padding 避让 ——
  后者要跟一串 flex 高度链（`.tabpane-body → .ask → .main → .col`）算账，
  实测差几十像素（用户原话「有间距啊」）。代价是它脱离文档流，所以 `.msgs` 要自己
  `padding-bottom` 让位，否则最后一条消息被压在输入框下面。
  ⚠️ 层级别再调乱：输入框 `5` < 遮罩 `6` < 抽屉 `7`（用户原话「层级不对」）。
- ⚠️ 这一格**自己管滚动**：`MeView` 里把 `.tabpane-body` 的滚动关掉了、并把它变成
  flex 容器（`.tabpane.ask-pane :deep(.tabpane-body) { display: flex; overflow: hidden }`），
  不关的话整页跟着滚、输入框会被推走，布局就散了。
  ⚠️ `.ask` 靠 `flex: 1 1 auto` **被拉伸**到满高，**别改成 `height: 100%`** ——
  百分比高度在那种父级下撑不起来（实测整格只有内容那么高、下面空一块）。

**流式**（2026-10-16 加）：这条链路**取数比写字慢得多**（3~4 轮工具调用，每轮一次大模型往返），
不流的话用户盯着转圈十几秒、不知道里头在干什么。SSE 事件：

| 事件 | 什么时候 | 前端拿它干什么 |
| --- | --- | --- |
| `round` | 进入第 N 轮 | 显示「正在查库…第 2/4 轮」，清掉上一轮的临时文字 |
| `step` | 一个工具跑完 | 「取值过程」**实时长出一条** |
| `delta` | 回答逐字 | 往当前气泡追加 + 光标闪烁 |
| `drop` | 这一轮的文字只是**旁白** | 撤回那段（模型常先说「I'll check your fills…」再去调工具） |
| `done` | 全部跑完 | 用完整结果盖掉 delta 拼出来的那份 |
| `failed` | 出错 | 一条错误气泡 |

⚠️ 这是**任务型**的流：断了不重连（重连 = 再问一遍、再花一次钱），
所以前端用裸 `EventSource`、收尾就关，不走 `liveSse` 那套看门狗重连。
⚠️ 没有任何新依赖：SSE 用仓库里现成的 `openSse`，Markdown 用
[markdown.ts](./frontend/src/markdown.ts)（那个"先转义再拼标签"的小渲染器，
它文件头写了为什么不引 marked）。

它**不能随便查库**：模型能做的只有「从下面这些工具里选一个 + 填参数」，
SQL 和口径都写死在 [backend/src/ask/tools.ts](./backend/src/ask/tools.ts)。

「我分析过什么」那半边（走 `analyses` / `knowledge` / `candles` / `llm_usage` / `persist_sessions`）：

| 工具               | 读什么                              |
| ------------------ | ----------------------------------- |
| `analysis_stats`   | 预测历史：按天 / 币种 / 档位统计    |
| `recent_analyses`  | 预测历史：原始结论（带档位与现价）  |
| `knowledge_search` | 知识库：我标过的案例                |
| `market_daily`     | 底座库的日线收盘（只覆盖 U 本位永续） |
| `usage_cost`       | 大模型用量与花费                    |
| `persist_status`   | 持久化分析的会话                    |

「我实际做了什么」那半边（走 `exchange_*` 那几张表，**只读库、不打交易所接口** ——
打接口要密钥、要按出口 IP 算的权重预算，而这几张表本来就是 WS 事件 + 每 5 分钟采样落下的）：

| 工具               | 读什么                                        |
| ------------------ | --------------------------------------------- |
| `exchange_fills`   | 逐笔成交：**汇总**（全区间）+ 最近 N 条明细   |
| `exchange_positions` | **历史仓位**：开仓→全平算一笔 + 盈亏统计（胜率） |
| `exchange_pnl`     | 盈亏汇总（已实现 / 手续费 / 资金费 / 净盈亏） |
| `exchange_ledger`  | 逐笔资金流水                                  |
| `exchange_account` | 净资产 / 可用 / 保证金率 / 当前持仓 / 近 7 天曲线 |
| `exchange_orders`  | 当前还挂着的委托                              |
| `exchange_c2c`     | C2C（法币）出入金订单                         |

⚠️ **「汇总」和「明细」是两条路，别混**：明细有条数上限（token 成本），
**汇总永远覆盖整个区间**。2026-10-16 实测踩过一次：30 天实际 **1554 笔**成交，
明细截到 500 条 —— 模型拿明细的条数去数，报成「500 笔」，少报三倍。
所以要「做了多少单」只认汇总里的 `总笔数`；要看逐笔就把 `from` / `to` 收窄，
而不是把 `limit` 开大。`exchange_positions` 同理（列表给了最近 N 笔，
「统计」那份是全量算的）。

⚠️ **历史仓位不是一张表**，是 `data/position-history.ts` 从**成交账本现算**的：
按币种把成交还原成一段段周期（0 → 有量 = 开仓，回 0 = 全平，中间减仓归到这一段），
资金费从钱账本按时间窗口归过来，`净盈亏 = 已实现 − 手续费 + 资金费`。
⚠️ 符号坑：**仓位的「手续费成本」是正数**（花掉多少），而
**盈亏汇总 / 资金流水里的「手续费」是负数**（现金流出）—— 两边不要混着说。

⚠️ 交易所那几个都取**默认那套 API Key**，明细里会写清是哪个账户（多账户才不会
被模型当成"全部账户"说出去）。成交 / 流水只覆盖**交易所保留期**内（币安约 3 个月）。

为什么不让模型直接写 SQL：全库的表都按 `user_id` 隔离，模型漏一次 `WHERE user_id`
就看到别人数据；而且 `档位` 这类口径让它现猜会飘。**参数是绑定值、SQL 是死字符串**，
可缓存也可离线评测。

几个必须知道的口径：

- **档位（可做 / 观望 / 不可做）不在库里** —— `analyses.verdict` 从 2026-10-11 起就没写过。
  统计时用 `verdictOf()`（跟持久化提醒、页面颜色同一个判定）**现算**。
  `grade`（A / A-W / S / V / B）同样只在结论正文里，**统计不了**。
- **相对日期以 system prompt 里那句「今天是 X」为准**。不给的话模型会拿训练数据里的
  年份当今年，算出个空区间，然后一本正经地说「你这段没有记录」。
  （见 [backend/src/ask/prompt.ts](./backend/src/ask/prompt.ts)）
- **时间一律北京**：`bjStamp()` 把毫秒转成 `YYYY-MM-DD HH:mm`。
  ⚠️ 别用 `toISOString().slice(0, 16)` —— 那是 UTC，比用户看到的早 8 小时，
  成交会被说成"前一天傍晚"（数字全对、时间全错，最难发现的那种错）。
- 参数收敛在 [backend/src/ask/range.ts](./backend/src/ask/range.ts)（**纯函数**，
  `npm run selftest` 里有一组夹具卡它）；取数循环在 [backend/src/ask/run.ts](./backend/src/ask/run.ts)，
  最多 4 轮工具调用。
- **没查库就答会被标出来**：一轮里一条工具结果都没有就直接开口的，前端打一个「没查库」的标
  —— 数据类问答最怕的就是它自己编。
- 每次问答按 **`ask`** 记账，在「我的 → 模型配置 → 用量统计」里能跟开单分析分开看。

**要加一类数据**：在 `tools.ts` 里加一个工具（参数 + 一段参数化 SQL），
再把它的含义补进 `prompt.ts` 的数据字典 —— 提示词里嵌着工具清单，
用户改不到那一半，所以这段提示词留在代码里、没进 `ai_docs`。

## 提示词

**写在代码里**，两份常量（`backend/src/llm/prompts.ts`）：

| 常量             | 干什么                                                             | 谁在用                 |
| ---------------- | ------------------------------------------------------------------ | ---------------------- |

  （原 `/prompts` 页已撤）。

  名字要保持一致，不然池子会膨胀；模板外的自造词会在存库前被丢掉。

## 花费怎么算

价目表按官方页手工维护（`backend/src/llm/pricing.ts`，单位：美元 / 1M token，**取高峰价**）：

| 时段     | 判定（北京时间）                                             | 单价     |
| -------- | ------------------------------------------------------------ | -------- |
| **高峰** | 周一~周五（**不含法定节假日**）9:00-12:00、14:00-18:00       | 基准价   |
| **空闲** | 其余全部 —— 含**周末全天**、**法定节假日全天**、平日其它时段 | **半价** |

- 判定在 `backend/src/llm/cn-holidays.ts`：节假日表 + 北京时间换算（先把时刻 +8 小时，
  再用 `getUTC*` 读）。⚠️ **节假日表每年国务院发通知后要手工更新一次**，文件头有说明。
- `npm run peak [年|年月]` 会把每一天的判定列出来，对着官方日历扫一眼就能核对。
- 改过表之后跑 **`npm run reprice`** 重算已落库的历史花费（先用不看写库，
  确认差异了再加 `--write`）。它只依赖库里已有的「下单时刻 + 用量 + 模型」，不重新调模型。
- **空闲时段必须按半价算** —— 周末与节假日全天都算空闲，这一项影响的钱不多但不能白交。

## 归档

每次分析落一行 `analyses`：

- `tags`（JSONB，带概率）、`grade_reason`（存的就是理由）、`verdict`、`price`、`snapshot`
- `snapshot` 里存的是当时**发了什么**：`{price, primary, blocks:[{timeframe,primary,days,bars}], heat}`
- 老记录的列（grade / checklist / outcome…）**没删**，只标了 `@deprecated`，历史还能读。

## 踩过的坑

- 端口 22、`github.com:443`、`api.binance.com` 在这个网络下不通；
  用 `fapi.binance.com` / `data-api.binance.vision`。
- `ai_docs.kind` 的 CHECK 约束改了要**同步改** `schema.ts` 里的迁移块，否则新 kind 插不进去。
- 页面白屏十有八九是**模板里用了一个已经被删掉的函数** —— 删函数一定要全局搜模板。
- 线上更新代码**必须** `--exclude='.env'`：服务器那份 `.env` 里有随机化过的
  `PGPASSWORD`，被本机那份覆盖后应用就连不上数据库（日志是「⚠️ 数据库不可用」）。
