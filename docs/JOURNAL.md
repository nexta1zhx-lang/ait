## 0. 用户定下来的

一路改下来的口径（原话都留着，改代码前先看这段，别把砍掉的又加回来）：

| 用户说 | 落地 |
|---|---|
| 「日记模块可以加入某些币种，总结」→「是我手动写日记，不一定每天」 | 条目式；正文纯 textarea，一个字都不生成 |
| 「**不要自动按月总结了**，默认排版，不显示什么总结，就是每日感想，可以筛选」 | 月度统计 / 缺口提示 / 月度总结框 **全删**；只有「币种 + 关键词」筛选 |
| 「**默认就是当前时刻不用写日期，有改动就更新时间**」 | 没有日期字段；条目的时间 = `updated_at`，列表按它倒序 |
| 「每条日记显示到分钟级，加点区分样式整体」 | `MM/DD HH:mm` + 每行前面一个圆点（展开那条圆点变蓝） |
| 「弹窗编辑的币种放在标题下方，定时刻显示的加上年月日，不需要一句话」 | 编辑器顺序：标题 → 币种（含定时刻，年月日时分）→ 正文；挂币不再有备注 |
| 「全部在搜索旁边，搜索框小一点」→「币种选择在左边字体放小，搜日记占剩余位置」 | 一行：**币种下拉在左（12px 字）** + 搜索框（吃满剩余）+ 加号 |
| 「页面整体加点样式设计，标题旁加个 ai 的图标，可以美化正文部分，输出是可以显示」 | 时间轴列表 + 展开卡片；编辑器「正文」旁一颗 ✨ 按钮 → 模型整理成 Markdown 的**预览**（不落库），点「用这段」才替换；正文按 Markdown 渲染 |

⛔ 这一页**没有任何模型调用**，也不打交易所 —— 纯读库写库，随便刷。

## 1. 两张表

| 表 | 存什么 | 关键点 |
|---|---|---|
| `journal_entries` | `title` / `body` + `created_at` / `updated_at` | **没有「写哪天」**；`day` 是老字段，插入时写北京时间的今天，读的时候没人用 |
| `journal_coins` | 一篇挂了哪些币 + `at_ts`（定住的那一刻，可空） | `(entry_id, base)` 唯一；一条最多 20 个 |

表定义在 [schema.ts](../backend/src/db/schema.ts)，读写全在 [journals.ts](../backend/src/db/journals.ts)。

> ⚠️ 曾经还有一张 `journal_months`（月度总结）。用户当天改口后**已从 schema 删掉**，
> 线上库里那张表还留着但没人读 —— 别再用它。
> ⚠️ `schema.ts` 里那段是 **JS 模板字符串**（`SCHEMA_SQL`），SQL 注释里**不能出现反引号**，
> 否则从这里截断、后面整段 SQL 都失效（踩过三次）。

## 2. 列表与筛选

`listJournalEntries(userId, {coin, q, limit, offset})`：

- **按 `updated_at` 倒序**（用户：「有改动就更新时间」）—— 新建的、刚改过的都在最上面。
- 每条的时间由 SQL 直接算成北京时间字面串：
  `to_char(updated_at AT TIME ZONE 'Asia/Shanghai', 'YYYY-MM-DD HH24:MI')`。
  前端只取后 11 位显示成 `10/18 14:32`，不再做时区换算。
- `coin`：这个币出现在 `journal_coins` 里才算命中。
- `q`：`title` 或 `body` 里**包含**这个词（`ILIKE`，`%` / `_` 已转义）。
- 两个一起给 = 同时满足。一页 30 条，`count(*) OVER ()` 带回总数，页面显示「还有 N 条」。
- 返回值里还有 `coins`：**写进过日记的全部币**（去重、按字母排）—— 筛选下拉的选项。

> ⚠️ 空关键词不能用 `ILIKE '%'` 短路：`title` 是可空列，`NULL ILIKE '%'` 还是 NULL，
> 没写标题的条目会被漏掉。所以 SQL 里写 `($3::text = '' OR ...)`。

## 2.1 AI 美化正文（2026-10-18）

用户：「标题旁加个 ai 的图标，可以美化正文部分，输出是可以显示」。

- 编辑器里「正文」标题右边一颗 ✨（`j-ai`）→ `POST /api/journal/polish`。
- 后端 `llm/polish.ts`：**只改写法、不改事实** —— 币种 / 时间 / 数字 / 方向 / 情绪原样保留，
  不许加交易建议、不许编数字、不写前言后语；输出是 Markdown。
- **不落库**：回来的是候选稿，页面用 `<AnswerBody>` 渲染成一块虚框预览，点「用这段」才写进正文，
  再走正常保存。`✕` 或关掉弹层就丢掉。
- 记账走 `recordUsage`（`kind='polish'`，用途显示「日记润色」），跟别的模型调用一个口径。

## 3. 条目

- 左边一条**时间轴**，每条一个圆点（展开的亮起来 + 光圈）；
- 第一行：`10/18 14:32 · 标题（没标题就用正文第一行）· ▾`；**挂的币折到第二行** ——
  手机上跟标题挤一行会把标题压成「按…」（实测）。
- 点一行展开：正文（**按 Markdown 渲染**，`softBreaks` 让「一行一句」不被并成一大段）
  + 每个币（有定时刻就显示 `2026-10-15 12:30`）
  + 两颗**图标**按钮（笔 = 编辑、垃圾桶 = 删除，`title` 里写着干什么）。
- 删除走**站内确认框**（`askConfirm`），不用 `window.confirm`。

### 3.1 每个币「定住的那一刻」

- 编辑器里每个币后面有一颗时刻按钮（没选时写「定时刻」，选过显示 `2026-10-15 12:30`）。
- 点开是**两步**：先点日历（今天之后禁用、可翻月、「今」一键回），再点在时/分两列
  （00-23 / 00-59）；选完分钟即收起。`◀` 回去改日期，`✕` 清掉（回到「不定」）。
- 点条目里的币 → 跳 K 线并**定在那一刻**（`chartFrom`）；没定就退回「这条日记的时间」。
  实测：定 `2026-10-15 12:30` 时拉的窗口是 10/11 00:30 → 10/20 00:30，**中心正好那一刻**。

## 4. 日期 / 时间控件是自己画的

用户：「日期改为自定义不用系统的，目前没显示全，显示到分」。

原生 `<input type="date">` / `datetime-local` 在手机 WebView 里长得完全不一样、窄屏还会被截断，
所以写了 [DateTimePick.vue](../frontend/src/comps/DateTimePick.vue)，三种模式：
`date` / `time` / `datetime`（两步）。

⚠️ 面板是**就地展开的下拉**（绝对定位），它活在 `.sheet`（`overflow:auto`）里：
  · 打开时会把滚动容器滚到面板完整可见（`reveal()`），否则挂币那行靠下、面板会露在弹层外；
  · `.dtp.open` 要抬 `z-index`，不然会被同级 `.j-add`（币种下拉）/ 后面几行币盖住、点不动。

## 5. 接口

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/journal/entries?coin=&q=&limit=&offset=` | 按最后改动时间倒序列出 |
| POST | `/api/journal/entries` | 新建 / 更新一条（带 `id` 就是更新；**不传时间**，服务器给 `now()`） |
| DELETE | `/api/journal/entries/:id` | 删一条 |
| POST | `/api/journal/polish` | 把正文交给模型整理（**不落库**，只回候选稿） |

挂币的每一项形如 `{base, at}`，`at` 是北京时间 `YYYY-MM-DD HH:mm`（空串 = 没定时刻）。

上限（后端卡死，前端不提示）：一条最多 20 个币、标题 120 字、正文 20000 字。
