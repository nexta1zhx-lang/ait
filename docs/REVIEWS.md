# 周期复盘（2026-10-22）

> 一句话：**自己选一段时间，看这一段的总结和每一段仓位的明细。只读，不参与下单。**
>
> 入口：`开单分析` → 左侧 **预测分析** → 二级 tab **复盘**

---

## 0. 它是怎么长成现在这样的

需求改了三轮，最后留下的东西跟第一版差很多，记下来免得以后又走回去：

| 时间 | 用户的说法 | 结果 |
|---|---|---|
| 最初 | 「不要限制我开单，开单之后给我状态和改进点」 | 先做了**盘中体检卡**（持仓中显示几 R、距止损、占账户） |
| 当天下午 | 「这个体验不用显示了」 | 体检卡整个**下线**（见 §6） |
| 当天晚上 | 「每笔和总结去掉，我可以自定义选一段周期来总结」 | 改成**周期复盘**：选时间范围 → 出总结 |
| 同上 | 「补历史去掉、默认同步去掉」 | 每分钟落库那套**停掉**，改成查询时**现场算** |
| 同上 | 「不要以每笔为单位，一次交易可能拆多个订单」 | 单位改成**仓位周期**，一张张成交挂在下面 |

**核心判断**：这个东西的价值不在「提醒你」，而在「让你看见自己的分布」。
所以它最终形态是一个**只读的归因视图**，不是一个会干预交易的系统。

## 2. 单位：仓位周期，不是成交

**一条成交 ≠ 一笔交易。** 用户实测一段仓位最多拆到 **22 张单**。

```
仓位周期 = 0 → 开仓 → (加仓 / 减仓) → 回到 0
成交     = 这个周期下面的一张张单（`orders`）
```

还原逻辑在 `backend/src/data/position-history.ts` 的 `buildCycles()`（这次没改它，直接复用）：

- 逐笔扫成交账本，仓位从 0 起来就是新的一段；
- 同方向 = 加仓，反方向 = 减仓，**反手**按量拆成「先结旧段、剩余开新段」；
- 回到 0 = 这一段结束。

⚠️ 账本不完整的那种（这一段第一笔本身就带 `realized`，说明开仓在账本覆盖之前）
会把开仓均价、持仓时长都变成残值 —— 这类段标 `partial`。

## 3. 最大浮盈 / 最大回撤怎么算

拿 DUSK 那个空单举例（数据可复核）：

```
开仓均价 0.12048851   平仓均价 0.12415220   数量 4713 张
窗口 10-18 02:48 → 10-19 21:24（42.6 小时，1m K 线 1979 根）
max(high) = 0.12963    min(low) = 0.11135
```

```
空单：最大浮盈 = (开仓 − 最低) ÷ 开仓 = (0.12048851 − 0.11135) ÷ 0.12048851 = +7.58%
      最大回撤 = (开仓 − 最高) ÷ 开仓 = (0.12048851 − 0.12963)  ÷ 0.12048851 = −7.59%

多单反过来：浮盈用最高价、回撤用最低价。

金额 = 百分比 × 开仓名义（开仓均价 × 数量）= 567.86 × 7.58% = +43.07 U
```

### 四个必须知道的边界

1. **这是「价格到过哪里」，不是你赚到的** —— K 线的 high/low 含**影线**，未必能成交在那个价。
2. **基准是加权开仓均价**，不随中途加仓调整 —— 加过仓的段数字会偏大。
3. **精度差异巨大**：`1m`（10-15 起）/ `15m`（09-22 起）/ `1h`（04-10 起）依次退化。
   一根 1h K 线的 high/low 对一个 5 分钟的仓位没有意义，所以每行右边**标出来**（`[1m]`）。
4. **这里的「回撤」是从开仓价算的最大不利偏移（MAE）**，
   不是「从浮盈高点回落」。后者 = `MFE − MAE`（这笔是 15.17 个百分点）。

### 那个边界坑（已修）

开仓 14:32 的仓位，覆盖它的那根 15m K 线是 **14:30 开盘**的。
按 `open_time >= 开仓时刻` 过滤会把这一根**漏掉** → 十来分钟的仓位一根都取不到 → MFE 全是 null。
修法是查询时**往回退一根**（`open_time >= 开仓 − 一个周期`）。

## 4. 接口（全 GET、只读）

| 路径 | 用途 |
|---|---|
| `GET /api/review-summary?from&to&keyId` | 周期总结（KPI + 按持仓时长 / 方向 / 币种） |
| `GET /api/position-cycles?from&to&keyId&limit` | 仓位明细（含 MFE/MAE 和逐笔成交） |

两个接口都**不读** `trade_reviews` → 所以不需要「补历史」、也不需要后台同步。

性能：200 段仓位（含 MFE 计算）约 **2 秒** —— K 线查询按 8 条并发（连接池默认 10 条，
留两条给别的请求）。

## 6. 下线的东西（别再往回加）

### 盘中体检卡

`frontend/src/comps/PositionHealthCard.vue` 已删除，挂载点也移除了。

下线原因：卡上那个「止损位」是**算出来的结构位**（最近 3 根 15m 的低点，夹 0.4%~1.5%），
而用户交易所里真实挂着的是「开仓自动止损 −4%」的**另一张单**。两个价并排显示，
很容易被读成「系统推荐你把止损放在这」。

`GET /api/positions/live` 和 `data/position-live.ts` 还留着（数据和结构位算法有用），
只是前端不展示了。

### 默认同步

`server.ts` 里那个每分钟一跑的 `syncPositionJournal` **定时器已摘掉**（函数还在，可手动调）。
现在复盘是查询时现算，不落库 → 少一轮白跑的 SQL。
