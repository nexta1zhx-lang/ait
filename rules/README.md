# rules/ —— 我的规则（AI 每次都会读）

这个目录**不在网页上编辑**，直接用编辑器改、用 git 管版本。
每次开单分析，系统会把这里的文件全部读进去喂给 AI。

## 文件怎么分工

| 文件                | 作用                                                              |
| ------------------- | ----------------------------------------------------------------- |
| **`主提示词.md`**   | AI 的**角色设定**（system）—— 你是谁、我的体系是什么、你怎么回答  |
| **其它 `*.md`**     | **规则正文** —— 理念、三档、Checklist、绩效基准，作为判断依据注入 |
| `_` 开头 / `README` | **跳过**，当作参考资料留着（比如 `_原始-AI辅助提示词.md`）        |

```
rules/
├── 主提示词.md              ← 角色设定（改这里调 AI 的判断风格）
├── 交易规则与方法.md          ← 规则正文
└── _原始-AI辅助提示词.md      ← 旧版留档，不会被读取
```

## 输出格式不用管

AI 的最后输出被**代码固定**成一段 JSON（判档 / Checklist / 结论 / 止损 / 出场条件 / 结尾提醒），
这样才能在网页上渲染成卡片。这段契约写在 `src/llm/prompt.ts` 里，**不跟着你的文件走**。

所以你改 `主提示词.md` 时，只要管「AI 该怎么判断、用什么语气」，不用管格式。

## 为什么不做成网页编辑框

- 规则是**判断标准**，应该像代码一样可 diff、可回溯、可回滚
- 网页输入框容易被误改，且丢了就找不回来
- 你已经有现成的 markdown 习惯，直接写文件更顺手

改完不用重启服务 —— 每次分析都会重新读文件。

## 加新规则

往这个目录丢 `.md` 就行，会自动被读取。想分文件就分，比如：

```
rules/
├── 主提示词.md
├── 交易规则与方法.md
├── 情绪管理.md          ← 新增，自动生效
└── 某个币种的特殊处理.md
```

文件名以 `_` 开头则跳过（适合放草稿、旧的废弃规则）。
